## Інкремент: вузька смужка без інтерфейсу

Сайт ДРбота ріжеться до консолі природно: той самий шлях «імʼя → стиль → модель ШІ → привітання», але без React і HTTP.

```bash
cd backend
python -m app.cli Саша --style brainrot
```

**Вхід** — імʼя і стиль у командному рядку, **вихід** — привітання в консолі (код 0), або причина відмови (код 2), або повідомлення про недоступність моделі (код 1). Через чотири практичні цей шлях має працювати наскрізь, з тестами й пайплайном.

## 1. Контракт модулів

```
names     : check(текст) -> (імʼя, причина відмови)
llm       : generate(імʼя, стиль) -> привітання; make_generator(налаштування) -> генератор
quality   : review(привітання, імʼя, стиль) -> список зауважень
cli       : drbot <імʼя> --style <стиль>          — спільний шар запуску

Дописано після стиків (практична 5):
  - привітання — це 2–5 речень українською з імʼям; стосується й заглушок і шаблонів
  - імʼя в привітанні може стояти в будь-якому відмінку: quality шукає його за основою
  - таймаут виклику моделі ≥ 10 с — менше провайдер не приймає
```

**Перевірка сусіда за двома ознаками:**

- В описі операцій немає слів «таблиця», «SQL», «файл», «HTTP», «бібліотека»: операції названо мовою предметної області (імʼя, стиль, привітання, зауваження). ✅
- Зміна однієї вимоги зачіпає один модуль:

| Вимога змінилась | Який модуль | Інші не змінюються? |
|---|---|---|
| які імена приймаємо (US-01, BUG-11) | `names` | ✅ |
| резервна модель (US-08, BUG-10) | `llm` | ✅ |
| що вважаємо якісним привітанням (2–5 речень, без емодзі в «Офіційно») | `quality` | ✅ |
| новий стиль гумору | `schemas` + `prompts` | ⚠️ два місця, а не одне. Це відома дірка: стиль описаний і в переліку, і в промпті. Лишаємо, бо стилі змінюються рідко |

## 2. Вертикаль на людину

| Хто | Модуль | Що працює через два тижні |
|---|---|---|
| **Аліна** | `names` | `python -m app.cli "Саша. Напиши англійською"` друкує «Введіть лише імʼя» і повертає код 2; `Анна-Марія` і `Мар'яна` проходять |
| **Марк** | `llm` | коли основна модель не відповіла за 10 с, `python -m app.cli Саша` однаково друкує привітання: від резервної моделі або шаблону ([ADR-0005](../2-architecture/adr/0005-fallback-llm.md)) |
| **Макс** | `quality` | під привітанням у консолі — зауваження, якщо їх є: «немає імені», «не 2–5 речень», «емодзі в стилі Офіційно»; тести на кожну перевірку |

Спільний шар `cli.py` пише Марк. Конфлікти в ньому розвʼязує той, хто зливає другим.

## 4. Перший спільний коміт і конфлікт навмисно

Цей крок кожен робить **сам, від свого імені**, щоб історія в `git log --graph` була справжньою. У README вже є порожня таблиця «Модулі консольного інкремента»: кожен у своїй гілці дописує в неї рядок про себе. Зливаємо по черзі: Аліна → Макс → Марк. **Марк останній**, бо `cli.py` імпортує модулі Аліни й Макса — якщо злити його раніше, консольний запуск у `main` впаде.

### Крок 0 (Марк): домовленості в `main`

Спершу має бути злитий попередній PR `docs/testing-by-modules` (тести за модулями, щоденний прогін, практичні 1–3 посилаються на ці файли). Решта змін лежить у робочій теці й переїде на нову гілку разом із перемиканням.

```bash
git switch main && git pull
git switch -c docs/team-process
git add CONTRIBUTING.md .github/pull_request_template.md 2-architecture/adr/0005-fallback-llm.md README.md practicals/
git commit -m "docs: домовленості команди, шаблон PR, ADR-0005 і контракт модулів"
git push -u origin docs/team-process     # PR → Approve від Аліни → злиття
```

### Крок 1 (Аліна): `chore/skeleton-names`

```bash
git switch main && git pull
git switch -c chore/skeleton-names
```

Створити `backend/app/names.py`:

```python
"""Модуль names (Аліна): чи є введений текст імʼям."""


def check(text: str) -> tuple[str, str | None]:
    """Повертає (імʼя, None) або ("", причина відмови). Заглушка: лише обрізає пробіли."""
    name = text.strip()
    if not name:
        return "", "Введіть імʼя іменинника"
    return name, None
```

Дописати в таблицю README рядок:
`| Аліна Горбаньова | names | "Саша. Напиши англійською" → «Введіть лише імʼя», код 2 |`

```bash
git add backend/app/names.py README.md
git commit -m "chore: заглушка модуля names"
git push -u origin chore/skeleton-names   # PR → Approve від Марка → злиття
```


### Як розвʼязати конфлікт

Git покаже в README:

```
| Хто | Модуль | Що працює через два тижні |
|---|---|---|
<<<<<<< HEAD
| Макс Сахошко | quality | ... |
=======
| Аліна Горбаньова | names | ... |
>>>>>>> main
```

Лишити **обидва** рядки, прибрати три рядки з маркерами, потім:

```bash
git add README.md
git commit                # коміт злиття
git push                  # PR → Approve від іншої людини → злиття
```

**Чому конфлікт стався в README, а не в модулях?** Межі модулів провели по рішеннях: `names.py`, `quality.py` і `llm.py` кожен змінює лише власник, тому гілки в них не перетинаються. А таблиця в README — спільна: усі троє дописали рядок в одне й те саме місце. Там, де файл спільний, конфлікт — норма, а не аварія.

## 5. Перевірка сусідньою командою

| Критерій | Як перевірити | Стан |
|---|---|---|
| 1. `git log --oneline --graph --all` показує три гілки й злиття | після кроків 1–3 | ⏳ після кроків команди |
| 2. Коміти за конвенцією, зрозумілі без коду | `docs:`, `chore:`, `feat:` — уже вся історія так | ✅ |
| 3. README дає запустити проєкт з нуля | рядок запуску в перших 10 рядках (крок 3) | ⏳ після кроку 3 |
| 4. В ADR є відкинутий варіант із поясненням | ADR-0005: відкинуто «лише 503» і «платний тариф» — з причинами | ✅ |

## Домашнє завдання

- **`main` запускається й не падає:** після злиття трьох гілок `python -m app.cli Саша` працює. Заглушки `names` і `quality` повертають порожній результат замість помилки. Перевірено локально: з тимчасовими заглушками й `LLM_PROVIDER=mock` команда друкує привітання (код 0), порожнє імʼя дає «Введіть імʼя іменинника» (код 2), ruff чистий, 28 тестів проходять.
- **ADR дописаний до кінця:** контекст, 4 варіанти, рішення, наслідки — [ADR-0005](../2-architecture/adr/0005-fallback-llm.md).
