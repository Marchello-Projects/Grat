Інкремент — консольна команда: імʼя і стиль на вході, привітання на виході ([практична 4](04-repo-process.md)).


## 1. Запуск на столі

Стан на початок пари: **«не зібраний з трьох гілок»**. Заглушки з практичної 4 підготовлені, але жодна гілка ще не злита — у репозиторії лише `main` і `docs/testing-by-modules`. Чому: кроки практичної 4 кожен мав зробити сам, від свого імені, і ніхто не почав, бо попередній PR (`docs/testing-by-modules`) теж висить незлитим. Тобто гілка живе вже тиждень — найчастіша причина, яку називає завдання. Борг першим ділом: злити попередній PR і пройти кроки 0–3 практичної 4.

## 2. PR на свою вертикаль

Кожен модуль доведено до реальної поведінки, з тестами. Один PR — одна думка, до 200 рядків разом із тестами.

## 3. Ревʼю сусіда

Хто кого рецензує: Аліну — Марк, Макса — Аліна, Марка — Макс. Нижче зауваження, які знайшлись при підготовці. Кожне — у формі «спостереження → наслідок». **На парі ревʼюер формулює їх своїми словами в GitHub**, а автор відповідає правкою або аргументом.

### PR 1 (`names`), ревʼюер Марк

1. `FORBIDDEN` містить цифри: `Агент 007` відхиляється, але й нікнейм `Kate2` теж. Користувач, який вітає друга за ніком, отримає «Введіть лише імʼя» без пояснення, що не так з цифрою.
2. Лапки заборонені: `«Сонечко»` відхиляється. Пестливе прізвисько в лапках — звичний спосіб вітати друзів, тож відмова тут буде несподіваною.
3. Перевірка працює лише в консолі: `schemas.py` для сайту її не викликає. Через сайт BUG-11 відтворюється так само, як і раніше.

### PR 2 (`quality`), ревʼюер Аліна

1. Основа імені — без останньої літери, тож «Саше» (неправильний кличний, баг `flash-lite` з 30.10) проходить як правильне. TC-48 цей модуль не ловить.
2. «Не українською» спрацьовує, лише коли латиниці більше за кирилицю. Привітання з цілим англійським реченням усередині пройде без зауважень.
3. Речення рахуються за `.!?…`, тож останнє речення, що закінчується емодзі без крапки («…мем у стрічці 🚀»), не рахується. У шаблоні брейнроту 3 речення, а модуль бачить 2. Межа «2–5» спрацює хибно на тексті з 1 реченням і емодзі.

### PR 3 (`llm`), ревʼюер Макс

1. Резерв ловить лише `LLMBusy` і `LLMUnavailable`. Адаптер Claude ловить не всі помилки SDK, тож несподіваний виняток пройде повз ланцюжок, і замість шаблону користувач побачить падіння.
2. Резерв **ховає помилки налаштування**: на прогоні неправильний таймаут дав `400` від Google, а користувач тихо отримав шаблон. Якщо ключ зламається, ми дізнаємось про це лише з логу. *(Відповідь автора, Марк: додано в наслідки ADR-0005; лог із причиною вже пишеться.)*
3. Щоденний прогін (`daily_run.py`) після злиття мірятиме продукт із резервом, а не модель: шаблони дадуть 14 з 14, навіть коли Gemini лежить. Критерій TC-56 втратить сенс, якщо не записувати, яка ланка відповіла.

## 5. Що зламалось на стику і чому цього не було видно в модулях

Наскрізний запуск з першого разу знайшов **три** розбіжності. Кожна — про те, про що не домовились, а не про описку:

| Стик | Що зламалось | Чому не було видно окремо | Що дописали в контракт |
|---|---|---|---|
| `llm` (заглушка) ↔ `quality` | заглушка `mock` відповідає «[official] З днем народження, Саша! 🎉»: 1 речення й емодзі в «Офіційно». Перший запуск за README закінчувався попередженнями | кожен модуль тестували зі своїм фейком; заглушку писали для тестів сайту, а не як «привітання» | `generate(...) -> привітання` означає 2–5 речень українською з імʼям — **це стосується й заглушок**. Заглушку виправлено (2 речення, без емодзі; тести сайту не зачеплено), для запуску без ключа — `LLM_PROVIDER=templates`, що проходить перевірки (є тест) |
| `config` ↔ Gemini API | таймаут 8 с з ADR-0005 Google відхиляє: «Minimum allowed deadline is 10s». Резерв це сховав — обидві моделі «не відповіли», вийшов шаблон | у тестах Gemini підмінений фейком, справжній API бачить лише наскрізний запуск | таймаут ≥ 10 с — обмеження провайдера; виправлено в ADR-0005 і `.env.example` |
| `names` ↔ `quality` | `names` віддає імʼя в називному («Анна-Марія»), модель пише кличний («Анно-Маріє»). Пряме порівняння давало б «немає імені» на правильному тексті | домовленість «імʼя в будь-якому відмінку» (CR-04) була у вимогах, але не в контракті модуля | `review` шукає імʼя за основою, кожну частину подвійного імені окремо |

Окремо: у `cli` зауваження з `stderr` друкувались **вище** за привітання — буферизація `stdout`. Виправлено `flush=True`.

## Домашнє завдання

### Чужа людина запускає за README

Інструкція «Запуск за хвилину» в README (крок 3 практичної 4) — з `LLM_PROVIDER=templates`, бо без ключа й мережі вона дає чисте привітання. Перевірка: посилання людині з іншої команди без підказок. Усе, що доведеться пояснювати голосом, дописуємо в README. Очікувані кандидати: «яка версія Python» (3.12) і «як активувати `.venv` на Windows».
