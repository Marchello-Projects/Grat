# План релізу

## Версіонування

[SemVer](https://semver.org/lang/uk/) `MAJOR.MINOR.PATCH`:

- **MAJOR** — несумісна зміна API (див. «Сумісність» у [api.md](../2-architecture/api.md)); до v1.0.0 API вважається нестабільним.
- **MINOR** — новий інкремент або контрольна точка курсу.
- **PATCH** — виправлення дефектів без нових функцій (`v0.2.1`).

Кожна версія — тег git, запис у [CHANGELOG.md](../CHANGELOG.md) і Docker-образи з тим самим тегом.

| Версія | Контрольна точка | Що входить |
|---|---|---|
| v0.1.0 | КТ1 | MVP: FR-01, 02, 03, 06, 10; документи Теми 1 (+ чернетки решти) |
| v0.2.0 | КТ2 | ітерація 2: швидкість (BUG-03), інтереси, «Перегенерувати», повторна генерація, ліміт на IP, таймер 429 |
| v0.3.0 | КТ3 | ітерація 3: PostgreSQL, оцінки, «Копіювати», «Про сервіс», Locust; `docs.yml` зелений |
| v0.4.0 | КТ4 | ітерація 4 + стабілізація: довжина, «жорсткість», ревʼю NFR-5, усі Must/Should покриті тестами |
| **v1.0.0** | реліз | усе вище + розгортання на VPS, [user-guide.md](user-guide.md), [support.md](support.md) |

## Склад v1.0.0

- **Функції:** усі Must і Should — FR-01…FR-07, FR-09, FR-10, FR-14…FR-16; Could (FR-11, 12, 13, 17) — якщо пройшли тести до КТ4.
- **Не входить:** FR-08 листівки, FR-18 мови ([roadmap.md](roadmap.md)).
- **Якість:** критерії виходу з [test-plan.md](../4-quality/test-plan.md); немає відкритих дефектів «Критична» і «Висока».
- **Документація:** повний пакет у репозиторії, GitHub Release із нотатками.

## Оточення

| Оточення | Де | LLM | Призначення |
|---|---|---|---|
| Розробка | ноутбук: `npm run dev` + `uvicorn --reload` | `mock` або Gemini | щоденна робота |
| CI | GitHub Actions | `mock` | лінтери, тести, збирання образів, перевірка документів |
| Демо / продакшн | VPS 1–2 vCPU, 2 ГБ, `docker compose up -d` | Gemini (ключ у `backend/.env` на сервері) | користувачі |

## Стратегія випуску

1. Гілка `main` у стані «готово», CI зелений, системні кейси пройдено на реальному Gemini.
2. Оновити `CHANGELOG.md`: перенести `[Unreleased]` у нову версію з датою.
3. Тег: `git tag -a v1.0.0 -m "ДРбот v1.0.0" && git push origin v1.0.0`.
4. GitHub → Releases → **Draft a new release** → тег `v1.0.0`, нотатки з CHANGELOG, скриншоти з `prototype/`.
5. На сервері: `git fetch --tags && git checkout v1.0.0 && docker compose up -d --build`.
6. Перевірка після розгортання: `/api/health` → `200`; ручний прохід UC-01 на телефоні; лог без помилок 5 хв.
7. Повідомлення в Telegram-чатах — лише після кроку 6.

## План відкату

| Ситуація | Дія | Час |
|---|---|---|
| Після розгортання `/api/health` не `200` або 5xx у логах | `git checkout <попередній тег> && docker compose up -d --build` | ~5 хв |
| Провайдер LLM повільний чи недоступний | змінити `LLM_MODEL` (або `LLM_PROVIDER`) у `backend/.env`, `docker compose up -d backend` — без перезбирання | ~1 хв |
| Ліміт провайдера вичерпано | тимчасово `LLM_PROVIDER=mock` не вмикаємо в продакшні (користувачі отримали б заглушку) — показуємо 429 «спробуйте за хвилину» й чекаємо скидання ліміту | — |
| Невдала міграція БД (з v0.3) | `alembic downgrade -1`, потім відкат образів; перед міграцією — `pg_dump` | ~10 хв |

Відкат вважається успішним, коли `/api/health` → `200` і UC-01 проходить на попередній версії.
