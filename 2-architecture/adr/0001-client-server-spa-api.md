# ADR-0001. Клієнт-серверна архітектура: React SPA + FastAPI

- **Статус:** прийнято
- **Дата:** 19.10.2026
- **Учасники:** Б (архітектор), А (PO)

## Контекст

Потрібен вебзастосунок, що працює в мобільних браузерах, викликає LLM API з секретним ключем, показує стани завантаження й помилок і має бути зрозумілим для команди з 2–3 студентів за семестр. Навантаження мале (≈ 2 запити/с у стрес-сценарії), вузьке місце — зовнішній LLM.

## Варіанти

1. **Лише фронтенд**, LLM викликається з браузера — найпростіше, але ключ API видно кожному.
2. **Монолітний серверний рендеринг** (FastAPI + шаблони Jinja) — один процес, але інтерактивні стани на клієнті робити незручно.
3. **React SPA + REST API на FastAPI** — два контейнери, чіткий контракт.
4. **Мікросервіси** (окремі сервіси генерації, статистики, листівок) — гнучко, але надмірно для команди й навантаження.

## Рішення

Варіант 3. React (Vite) збирається в статику, яку віддає nginx; FastAPI надає `/api/*`; nginx проксіює `/api` на бекенд, тож у продакшні фронтенд і API на одному домені.

## Наслідки

- ➕ Ключ API тільки на сервері; бекенд і фронтенд тестуються окремо; автоматична документація OpenAPI (`/docs`).
- ➕ Статика не навантажує бекенд.
- ➖ Два Docker-образи й CORS у розробці (розвʼязано проксі Vite).
- ➖ Python і JavaScript — два стеки в одній команді; розподіл ролей у [process.md](../../1-lifecycle/process.md).
