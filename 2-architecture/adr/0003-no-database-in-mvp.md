# ADR-0003. Без бази даних у MVP, PostgreSQL з v0.3

- **Статус:** прийнято
- **Дата:** 19.10.2026
- **Учасники:** Марк Паскалов (архітектор, DevOps)

## Контекст

MVP (FR-01, 02, 03, 06, 10) нічого не зберігає: користувач отримує текст і копіює його. Збереження потрібне пізніше: оцінки (FR-14), лічильник генерацій на добу (NFR-2), статистика стилів, листівки (FR-08).

## Варіанти

1. **SQLite з першого дня** — просто, але блокує запис за одночасних звернень; у стрес-сценарії (≈ 20 одночасних генерацій) стане проблемою.
2. **PostgreSQL з першого дня** — правильно для продакшну, але міграції й контейнер БД уповільнюють MVP, а зберігати поки нічого.
3. **Без БД у MVP, PostgreSQL + Alembic з v0.3** (ітерація 3), коли зʼявляться перші дані.

## Рішення

Варіант 3. Модель даних спроєктовано заздалегідь ([data-model.md](../../3-implementation/data-model.md)), щоб v0.3 не ламала API.

## Наслідки

- ➕ MVP швидше; менше персональних даних — нічого не зберігається.
- ➕ Docker Compose поки з двох сервісів.
- ➖ Денний ліміт NFR-2 до v0.3 не контролюється сервером — лише лімітами провайдера.
- ➖ Перехід потребує міграцій і оновлення CI (тестова БД у GitHub Actions).
