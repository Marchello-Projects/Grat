# ADR-0005. Резервна модель ШІ

- **Статус:** запропоновано (Марк Паскалов, 07.11.2026); на погодження команди й викладача — разом зі зміною вимог CR-07
- **Пов'язано:** [ADR-0002](0002-llm-provider-gemini.md), BUG-10, ризик R-02

## Контекст

Продукт тримається на одній моделі ШІ — безкоштовному тарифі `gemini-3.8-flash` ([ADR-0002](0002-llm-provider-gemini.md)). Щоденний прогін тестів показав, що цього недостатньо: **за 4 дні — 0 привітань із 56 запитів** ([test-report.md](../../4-quality/test-report.md), розділ 4). Причини:

- модель перевантажена: більшість викликів закінчуються `504 DEADLINE_EXCEEDED` або `503`;
- ліміти безкоштовного тарифу — **20 запитів на добу і 5 на хвилину** на модель, а невдалі виклики з повтором теж їх витрачають;
- 02.11 інша модель того самого провайдера (`gemini-3.5-flash-lite`) теж відповідала `504`.

Це найдорожче рішення в проєкті: від нього залежить, чи отримає користувач привітання взагалі. Бюджет на API — $0 (CR-01).

## Варіанти

| Варіант | Плюси | Мінуси | Рішення |
|---|---|---|---|
| 1. Лишити одну модель і повертати 503 (як зараз) | нічого робити не треба | 0 з 56 у тестах — продукт не працює | ❌ відкинуто: саме це й є дефект |
| 2. Платний тариф Gemini або Claude API | вищі ліміти, стабільніше | бюджет $0; Claude потребує передоплати (CR-01) | ❌ відкинуто для v0.2; лишається варіантом, якщо зʼявиться бюджет — адаптер Claude уже є |
| 3. Резервна модель того самого провайдера (`flash-lite`) | безкоштовно; окремі ліміти на кожну модель; відповідала за 1–8 с 30.10 | коли перевантажений сам Google — падають обидві (02.11) | ✅ частина рішення, але не одна |
| 4. Ланцюжок: основна модель → резервна модель → готові шаблони | користувач **завжди** отримує привітання; безкоштовно | шаблон не такий смішний і не персональний | ✅ **обрано** |

## Рішення

Варіант 4. Генератор отримує **список** моделей із `.env` і пробує їх по черзі:

1. `gemini-3.8-flash` — таймаут **10 с** (менше Gemini API не приймає: «Minimum allowed deadline is 10s», знайдено на практичній 5), **без повтору** (повтор лише витрачає ліміт);
2. `gemini-3.5-flash-lite` — окремий ліміт, таймаут 10 с;
3. **шаблони** — 5–10 заздалегідь написаних і перевірених на NFR-5 привітань на кожен стиль, з підстановкою імені; працюють без мережі.

У лозі пишемо, яка ланка відповіла. 503 повертається лише тоді, коли впали всі ланки — тобто ніколи для шаблонів.

## Наслідки

- ➕ Шлях користувача не обривається на кроці «Згенерувати» (межа MVP з [практичної 2](../../practicals/02-requirements-mvp.md)).
- ➕ Добовий ліміт витрачається вдвічі повільніше: немає повтору на перевантаженій моделі.
- ➖ У найгіршому разі (обидві моделі мовчать) користувач чекає 2 × 10 с і лише потім отримує шаблон — це довше за NFR-1. Менший таймаут Gemini не приймає.
- ➖ Резерв **ховає помилки налаштування**: неправильний ключ чи таймаут виглядають як «модель не відповіла», і користувач тихо отримує шаблон. Тому кожен перехід на наступну ланку пишемо в лог з причиною.
- ➖ Частина привітань буде шаблонною. Користувачу це видно не буде; міримо частку шаблонних у лозі. Якщо їх > 30 % — повертаємось до варіанта 2.
- ➖ Змінюються вимоги: NFR-4 «повертає 503» → «≥ 95 % запитів закінчуються привітанням» (CR-07), а TC-58 стає регресійним тестом.
