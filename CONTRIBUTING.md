# Як ми працюємо

Домовленості команди ДРбота. Записані один раз — більше не обговорюємо. Подробиці з прикладами — у [git-workflow.md](3-implementation/git-workflow.md).

## Гілки

- **Гілка на задачу**, від свіжого `main`: `feat/name-guard`, `fix/bug-10-fallback`, `docs/adr-0005`, `test/quality-checks`, `chore/skeleton-names`.
- Гілка живе **не довше двох днів**. Не встигаєш — розбий задачу на менші.

## Коміти

Формат: `тип: що змінено` — зрозуміло без відкриття файлу.

| Тип | Коли |
|---|---|
| `feat:` | нова поведінка для користувача |
| `fix:` | виправлення дефекту (з номером: `fix: резервна модель (BUG-10)`) |
| `docs:` | документи |
| `test:` | тести без зміни поведінки |
| `chore:` | каркас, налаштування, залежності |

## Злиття

- У `main` — **тільки через pull request** за [шаблоном](.github/pull_request_template.md).
- **Свій PR не зливаємо самі:** Approve дає інша людина. Ревʼюер, який не читає код, перевіряє поведінку — запускає зміну за пунктом «як перевірити».
- Перед злиттям CI зелений: ruff, pytest, ESLint, Vitest.

## Модулі

Одна людина — один модуль і його тести; контракт модулів — у [practicals/04-repo-process.md](practicals/04-repo-process.md). Чужий модуль змінюємо лише через PR його власника. Спільний шар запуску `backend/app/cli.py` — конфлікти в ньому розвʼязує той, хто зливає другим.

## Ніколи не потрапляє в git

Секрети (`.env`, ключі API) і згенероване (`.venv/`, `node_modules/`, `dist/`, кеші) — усе вже в `.gitignore`. Ключ випадково закомітили — одразу відкликати його в Google AI Studio, а не лише видалити з історії.
