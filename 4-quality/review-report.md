## Чек-лист

### SRS

- [x] Кожна вимога має унікальний ID
- [x] Кожна FR має критерії приймання, які можна перевірити
- [x] NFR задано числом, з умовами й способом перевірки
- [x] Пріоритети MoSCoW, межа MVP
- [ ] Немає неоднозначних слів («швидко», «новий», «зручно») — див. RV-02, RV-04
- [ ] NFR досяжні в наших обмеженнях — див. RV-01
- [x] Є глосарій

### API

- [x] Кожна операція має запит, відповідь, коди помилок, приклад
- [ ] Формат помилок однаковий для всіх кодів — див. RV-07
- [x] Версія контракту вказана
- [ ] Є все, що потрібно для запланованих функцій — див. RV-09, RV-10

### Архітектура

- [x] Стиль обґрунтовано, порівняно альтернативи
- [x] Є діаграми контексту й контейнерів
- [ ] Немає єдиних точок відмови без плану — див. RV-12
- [ ] Обмеження ресурсів працюють при масштабуванні — див. RV-11
